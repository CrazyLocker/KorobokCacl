## Вердикт

Функционально ядро готово: расчёт сходится с прототипом, версии, клиенты, заказы и мягкое удаление работают,
миграции проходят на пустой базе. **P0 закрыты**, кроме одного: P0-1 (пароль на изменяющие ручки) на время
первого альфа-теста снят и зафиксирован как **принятый риск** — база чистая, пользователь один, машина
локальная; защита на этот период — `127.0.0.1`, суженный CORS, `baseline-on-migrate: false` и `pg_dump`
перед первым запуском. Остались P1/P2 — их можно вести параллельно.

### P0-1 — принятый риск на альфу

База чистая, пользователь один, машина локальная. Пароли на мутирующие ручки сняты до первого
теста. Защита на этот период: `127.0.0.1`, CORS сужен, `baseline-on-migrate: false`, `pg_dump`
перед первым запуском. Перед любым использованием на данных, которые жалко, — вернуть
аутентификацию (коммит `50792b6` в истории, восстановить точечно).

Что именно ослаблено (`eaa727f`, `1ad8030`): `SecurityConfig` снова `permitAll` для `/api/**`,
удалены `AdminProperties`, `AuthController` и `GET /api/auth/me`; на фронте убраны
`adminAuth.ts`, `AdminGate` и запрос пароля, в `sessionStorage` ничего не пишется.
Что осталось без изменений: `server.address=127.0.0.1`, CORS только dev-сервер Vite,
springdoc/swagger выключены, `baseline-on-migrate: false`, `pg_dump` — обязательный шаг
чек-листа дня релиза.

Раздел с описанием блокеров ниже сохранён как исходная формулировка находок.

### P0-1. Потеря данных: необратимые операции без ограничения доступа и без страховки

`modules/security/.../SecurityConfig.java:39-56` — `permitAll` на все `/api/**`, включая физическое стирание:
`POST /api/calculations/purge`, `DELETE /api/calculations/{id}`, `DELETE /api/orders/{id}` и импорт справочников
(перезапись одним запросом). Страховки нет: бэкап нигде не предусмотрен, `baseline-on-migrate: true` только усугубляет
(при потере истории Flyway прогонит V2..V23 поверх живых данных, включая `DELETE FROM constructs`).
Риск: один неверный вызов — и расчёты, заказы или справочник исчезли без возможности восстановить.
Что сделать до альфы: пароль хотя бы на изменяющие и удаляющие ручки; `pg_dump` — обязательный шаг перед запуском
и перед импортом справочников; purge доступен только «альфа-администратору».

### P0-2. Сетевая экспозиция: сервер в сети, CORS `*`, открытый Swagger

`server.address` не задан → Tomcat слушает все интерфейсы (`0.0.0.0:8080`); `SecurityConfig.java:68-79` —
CORS `allowedOriginPatterns("*")` + `allowCredentials(true)`; `/swagger-ui/**`, `/v3/api-docs/**` в `permitAll`;
`:59` httpBasic без `UserDetailsService` (Spring печатает сгенерированный пароль в консоль).
Риск: приложение доступно всей локальной сети, а любая открытая в браузере страница может дёргать API и читать ответы
от имени пользователя. Для одного технолога за его машиной это терпимо ровно один день.
Что сделать до альфы: `server.address=127.0.0.1`, CORS сузить до `http://localhost:5173`, springdoc выключить.

### P0-3. Тихая нулевая цена печати при неизвестном/удалённом формате

`modules/api/.../controller/CalculatorService.java:290-298` проверяет только `format != null` и `quantity > 0`,
не сверяя формат с таблицей печати; `modules/calculator/.../PrintCostCalculator.java:69-75` при отсутствии таблицы
возвращает `BigDecimal.ZERO`. Проверено чтением кода: `printSettings{enabled:true, format:99}` даёт расчёт без печати
и цену ниже реальной — без ошибки и без предупреждения в UI.
Что сделать: 400 «Формат печати не найден» при неизвестном формате (и для сборки аналогично).

### P0-4. Устаревшая цена на экране и потеря несохранённой правки

Два дефекта одного сценария «печатаю и смотрю на цифры», поэтому закрываются одним шагом.

- Гонка пересчётов: `frontend/src/hooks/useCalculator.ts` — `calculate()` применяет ответ безусловно
  (`setResult(response)`), запросы не отменяются и не нумеруются (в `src` 0 вхождений `AbortController`/`signal`).
  При медленном первом ответе на экране остаются цены предыдущего состояния, а `calc.loading` нигде не показывается.
- Потеря работы: нет `beforeunload`, нет черновика в `localStorage`, смена конструкции в `CalculatorPage.tsx`
  не спрашивает подтверждения, `openCalculationEditor` делает `window.location.assign`. 10–20 минут ввода исчезают молча.

Что сделать (в этом порядке): `AbortController` + «применять только последний ответ», затем **индикатор загрузки**
(`calc.loading` в блоках цен), и только после него — `beforeunload` + подтверждение смены конструкции.

### P0-5. После сохранения версии URL указывает на старую версию

`useCalculator.ts` (`applySavedVersion`) обновляет только state; `history.replaceState` в проекте нет (0 вхождений).
Итог: F5 после сохранения v2 открывает v1, а следующая правка создаёт ветку от устаревшей версии —
дерево расходится с тем, что видел менеджер.
Что сделать: `history.replaceState` на id сохранённой версии.

## Важное (P1) — до или сразу после первого показа

**Установка и воспроизводимость**
- Креды БД зашиты в `modules/api/src/main/resources/application.yml:6-8` (`postgres` / `4meonl`), профилей и env-переопределения нет; пароль в git-истории.
- Нет шага создания БД: Flyway создаёт таблицы, но не саму базу; ни `docker-compose`, ни `scripts/init-db.sql`; версия PostgreSQL не зафиксирована (README «15+», локально 18.6).
- Нет артефакта фронта рядом с бэкендом: только `npm run dev` на 5173 с прокси на 8080. Для технолога — либо `npm run build` + раздача `dist` из Spring, либо одна инструкция «две консоли».
- `baseline-on-migrate: true` (`application.yml:22`): при потере `flyway_schema_history` Flyway прогонит V2..V23 поверх живых данных, включая `DELETE FROM constructs` (V3).

**Данные**
- Деструктивные миграции без откатов и без бэкапа: V3 (`DELETE FROM constructs`), V14 (удаление прайсов/конструкций/деталей), V17 (`DROP TABLE materials`), V13/V21 (`DROP COLUMN`); down-секций нет ни в одной из 23.
- Справочник неполон: `docs/features/construction-todo.md` — Эгеон 4/25/42 (`perKey`/`perSheet` ПВХ = 0-заглушка), Этне 10 (8 или 10), Этне 4 (6/30 унаследовано). Расчёт по ним молча даёт неверную цену — до ответа технолога помечать в UI.

**Надёжность бэкенда**
- `GlobalExceptionHandler` на 500 отдаёт `ex.getMessage()` (утечка текста JDBC/Jackson) и падает на `null` message; нет обработчиков битого JSON и невалидного UUID → 500 вместо 400.
- Автонумерация заказов (`CalculationOrderService.resolveNumber`) не учитывает ручные номера и гонку → `DataIntegrityViolation` → 500.
- `importPriceLists` и `importPrintTables` без `@Transactional` (`ReferencesController`) — половина справочника обновится при ошибке.
- Нет ни одного теста с БД/Spring-контекстом (`@SpringBootTest`/`@DataJpaTest`/Testcontainers): миграции, JSONB, каскады и `ddl-auto: validate` проверяются только руками.
- Нет CI: `.github` отсутствует, 23 PR смержены без автоматических гейтов.

**UX, влияющий на цену**
- Детали из раскладки попадают в расчёт с `sheetPrice = 0` (TODO в `useCalculator.ts`) — себестоимость занижается без предупреждения.
- `PriceListTab`: `.catch(() => setPriceData({}))` — «нет прайса» и «сервер упал» выглядят одинаково; сохранение без id создаёт дубль прайса.
- `getOperations` может перезаписать доп. операции восстановленного расчёта (гонка на монтировании).
- Две независимые формулы себестоимости на одном экране (локальная и `calc.result.totalCost`) — поднято до стоп-гейта чек-листа (п. 7): перед показом технологу сверить обе на эталоне «Паллена 9»; расхождение хотя бы на копейку останавливает релиз, потому что две разные цены на одном экране убивают доверие к альфе.
- Нет Error Boundary — любое исключение в рендере даёт белый экран.

**Документация и эксплуатация**

## Что уже нормально

1. Версии и мягкое удаление непротиворечивы: `root_id`/`parent_id`/`version`, `iterate` запрещает правку помеченной версии, `delete` помечает подветку BFS, `purge` только для помеченных и блокируется при наличии заказа; FK-каскады и `ON DELETE SET NULL` у заказов — висячих ссылок нет.
2. Расчётное ядро сверено с прототипом: `prototype-comparison-report.md` — 7 из 7 тиражей совпадают (80 ₽ себестоимость → 110 ₽ без НДС → 122 ₽ с НДС на 10–49).
3. Доменные ошибки на русском, 400/404 разделены, единый формат ответа; на фронте — интерсептор с человеческими текстами.
4. Серверная валидация расчёта не декоративная (детали, количество на листе, тираж против деталей, тиры прайс-листа).
5. Парсинг SVG ножа безопасен: внешние DTD отключены, пустой `EntityResolver`, ошибки уходят в `parseError`.
6. Восстановление версии полное и не зависит от справочника; взаимоисключение «печать/сборка» реализовано в одном месте и совпадает с бэком.
7. Разрушающие операции в UI идут через `modal.confirm` с красной кнопкой и честным текстом; 0 `console.*`, 2 TODO на весь фронт.

## Чек-лист дня альфа-релиза

1. `pg_dump -Fc korobki > korobki_pre_alpha.dump` **до** первого запуска новой версии. Проверить, что в дампе есть `flyway_schema_history`: `baseline-on-migrate` для альфы выключен, поэтому при потере истории Flyway не станет прогонять V2..V23 поверх живых данных.
2. Убедиться, что БД и роль созданы, а креды совпадают с конфигом (или заданы через env). Пароля администратора на альфе нет: изменяющие ручки открыты (P0-1 — принятый риск, см. выше).
3. Запустить бэкенд, проверить `flyway_schema_history`: `max(version) = 23`, все `success = true`.
4. Вручную прогнать гейты: `.\gradlew.bat test`, `npm ci && npm run lint && npm test && npm run build`; результат зафиксировать.
5. Запускать `npm run build` + `preview` (не `dev`), бэкенд на `127.0.0.1:8080`.
6. Смоук по эталону «Паллена 9», тираж 10–49: 80 / 110 / 122 ₽; затем сохранение → версия → заказ → мягкое удаление → purge помеченного.
7. **Стоп-гейт «две формулы»** — ПРОЙДЕН на эталоне «Паллена 9» (35 ₽/лист, работа 5 ₽, наценка 30, прайс 10–49 = 79 ₽):
   - без печати: локальная формула «Коробка» `29.0000000000`, ответ API `28.9999999999` — в интерфейсе оба `29.00 ₽`;
   - печать включена, формат `500*350`, тираж 49: локальная `365.7346938775`, ответ API `365.7346938775` (`printCostPerUnit = 112.2448979592` = 5500 ₽ за 49 листов на тираж) — в интерфейсе оба `365.73 ₽`.
   Расхождение — только на уровне двоичной погрешности double (≈1e-9 ₽), на копейку и больше не расходится, поэтому релиз не останавливаем.
   Отдельно к этому гейту не относится, но остаётся P1: у деталей, пришедших из раскладки, `sheetPrice = 0`, и материал в себестоимость не попадает.
8. Поставить тег `alpha-0.1.0` на проверенный коммит.
9. Проговорить технологу ограничения: клише/конгрев/шелкография — заглушки; Эгеон 4/25/42 и Этне 4/10 — данные не подтверждены; откат — только из дампа.
