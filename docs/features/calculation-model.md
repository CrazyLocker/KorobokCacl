## 1. Глоссарий

| Термин | Значение |
|---|---|
| **Customer** (Заказчик) | Юрлицо или физлицо, которое заказывает коробки. Центральная сущность — к ней привязаны все заказы. |
| **Order** (Заказ) | Конкретный заказ от заказчика. Номер + статус + дата. |
| **Calculation** (Расчёт) | Итерация расчёта в рамках заказа. Хранит снапшот. Может быть корневым или дочерним. |
| **Knife** (Нож) | Инструмент для вырубки деталей. Глобальный справочник, переиспользуется между заказами. Никогда не удаляется. |
| **Part** (Деталь) | Элемент коробки: дно, крышка, обечайка, разделитель, вкладыш… Глобальный справочник. |
| **Snapshot** (Снапшот) | Денормализованное состояние расчёта на момент сохранения: цены, названия, ножи — значениями, не ссылками. |
| **Change type** | Тип изменения между расчётами: `cosmetic`, `additive`, `global`. |
| **КП** | Коммерческое предложение (PDF), которое видит заказчик: только стоимость коробки и нож. |

## 2. Схема связей
Customer (1) ──── (N) Order (1) ──── (N) Calculation
│
├── parent_id (0..1) → Calculation (дерево)
└── snapshot: JSON (полный)

Knife (1) ──── (N) Part ← деталь принадлежит одному ножу
Knife.customer_id ──── (1) Customer ← нож привязан к клиенту (для поиска)

Part ──── (1) Knife ← ровно один нож на деталь

text

**Правило:** `Knife 1—N Part`. Одна деталь → ровно один нож. Один нож → 1..N деталей. Бывает, что дно и разделитель рубятся одним ножом.

**Жизненный цикл ножа:**
- Нож **никогда не удаляется** — он использовался в расчётах и производстве.
- Физический износ (затупился) → **перевыпуск**: новый нож с новым номером, старый помечается `archived` (лежит на складе).
- `active` — используется, доступен для поиска в новых заказах.
- `archived` — не используется, но остаётся в старых расчётах. В поиске для новых заказов не показывается (или показывается с пометкой).

**Поиск ножей при повторном заказе:** по `customer_id` + `number`. Только `active` по умолчанию.

## 4. Дерево расчётов

### 4.1 Правила

- Первый расчёт в заказе — **корень** (`parent_id = null`, `change_type = null`).
- Косметическое или дополнительное изменение → **дочерний расчёт** (`parent_id = родитель`, `change_type = cosmetic|additive`).
- Глобальное изменение → **новый корень** (`parent_id = null`, `change_type = global`). Старый корень и его дети сохраняются.
- **«Вернуться к старому»** = **открыть старый расчёт как есть**, со снапшотом на момент расчёта (без пересчёта по текущим ценам). Если нужно пересчитать — создать новый расчёт на основе старого (клон с текущими ценами) — это отдельное действие, не «возврат».

### 4.2 Пример
Calculation #1 (корень: 4 конфеты, белый картон, дно+крышка+разделитель)
├── #2 (cosmetic: белый → красный)
│ └── #3 (additive: + логотип на крышку)
└── #4 (global: 9 конфет) ← новый корень
└── #5 (cosmetic: …)

text

## 5. Снапшот

### 5.1 Что входит

- Денормализованные значения: названия материалов, конструкций, операций, надбавок.
- Цены на момент расчёта: `manufacturing_cost`, `markup`, `tax`, скидки.
- Ножи: `number`, `name`, `total_length_mm`, `knife_cost` на момент расчёта (даже если нож потом архивирован).
- Детали: `name`, `part_type`.
- Итоги: стоимость коробки, стоимость ножа, итого.

### 5.2 Что не входит

- Ссылки на живые справочники (`material_id`, `construct_id`) — только денормализованные значения.

### 5.3 Почему полный снапшот, а не дельта

- **MVP:** простота, надёжность, быстрый доступ.
- Объём: 5–50 KB на расчёт, 10 расчётов на заказ, 1000 заказов = 50 MB. Не проблема.
- **Позже** (если станет тесно): переход на дельты + `applyDeltas`. Но не преждевременно.

> В коде уже `calculation: Map<String, Object>` — полный снапшот. Совпадает с решением.

## 6. КП (PDF)

### 6.1 Что видит заказчик
Коробка (материал, конструкция, тираж) ......... X ₽
Нож (разработка) ............................... Y ₽
──────────────────────────────────────────────────
Итого ......................................... X + Y ₽

text

- «Кухня» (себестоимость, наценка, скидки, НДС) — **не показывается**.
- **Повторный нож — строку не указываем вообще.** Если в расчёте использован архивный/переиспользованный нож (без разработки), строки «Нож» в КП нет.
- Если ножей несколько (по деталям) — разбивка по деталям, если заказчику важно. Иначе — одна строка «Нож» (для новых ножей).

### 6.2 Формат

- **PDF генерируется на фронте** (`@react-pdf/renderer`).
- Фронт получает данные расчёта из API и рендерит PDF в браузере, без серверной генерации.
