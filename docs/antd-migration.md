# Миграция WebCalc на Ant Design 6

Статус: план согласован, выполняется Этап 0.
Базовая ветка: `develop`.
Пилот: `frontend/src/components/NewAppAntd.tsx`.

## 1. Цель и границы

Перевести весь frontend на Ant Design 6 и полностью убрать MUI/Emotion:

- один UI-калькулятор вместо трёх вариантов;
- Ant Design используется для layout, навигации, форм, таблиц, диалогов и уведомлений;
- бизнес-логика, API, типы и движок раскладки не меняются;
- изменения выполняются отдельными PR, чтобы каждый этап можно было проверить и откатить независимо.

Пилот `NewAppAntd` уже подтверждён визуально и функционально. Его нельзя считать финальным: он пока находится внутри MUI-оболочки и использует MUI `Header`, `ViewToggle`, `SaveCalculationDialog` и `Snackbar`.

## 2. Принятые решения

1. **Один калькулятор.** Оставляем Ant Design-вариант. Классический и «Новый UI» удаляем только после ручной проверки паритета в Этапе 1.
2. **Тема.** Основной цвет Ant Design — `#1677FF`, шрифт Inter, радиус полей 8 px. Значения вынесены в общий `src/designTokens.ts`, чтобы MUI-тема и `antdTheme.ts` не дублировали палитру.
3. **Провайдеры.** `ConfigProvider` с локалью `ru_RU`, `antdTheme` и `App` из Ant Design подключаются один раз в `src/main.tsx`. Страницы не создают собственные провайдеры.
4. **Постепенное сосуществование.** Пока MUI-страницы не мигрированы, MUI и Ant Design работают вместе. MUI-пакеты удаляются только в финальном PR.
5. **E2E.** Для миграции достаточно ручного smoke-чеклиста, Playwright в Этапе 0 не устанавливается. Подробнее — в разделе 10.
6. **Совместимость API.** В запросы к backend не добавляются UI-поля. Клиентские идентификаторы строк таблиц не должны попадать в JSON запроса.

## 10. Решение по e2e

**Принято: для миграции используем ручной smoke-чеклист. Playwright в Этапе 0 не устанавливаем.**

Причины:

- в проекте нет тестового backend и стабильных fixtures для `/api/*`;
- UI-тесты потребуют маршрутизации запросов и поддержки тестовых данных, что расширит Этап 0 и смешает инфраструктуру тестирования с lint/theme/provider-изменениями;
- сейчас нет стабильных `data-testid` и стабильных идентификаторов строк — они появятся в Этапе 1;
- ключевой риск миграции — визуальные и поведенческие регрессии, которые на этом этапе быстрее закрыть структурированным ручным прогоном.

Чеклист обязателен для каждого PR, затрагивающего UI, и считается достаточным для приёмки миграции. Playwright остаётся отдельной задачей после Этапа 1: если появятся повторяющиеся регрессии или понадобится CI-защита, добавляем `@playwright/test`, фикстуры API и 5–7 smoke-сценариев.

## 13. Риски и меры

1. **`InputNumber` и дробный ввод.** `onChange` может вернуть `null`, а промежуточные значения вроде `"1."` не сохраняются. Для `LayoutPage` сохраняем собственный `NumberField`; для остальных полей проверяем `precision`, `step` и пустое значение.
2. **Индексы строк.** В пилоте `render` использует `index` для обновления деталей. После удаления/добавления строки это может изменить не ту запись. В Этапе 1 вводим клиентские стабильные идентификаторы, используем их в `rowKey` и в обработчиках, а перед отправкой в API удаляем служебное поле.
3. **`sx` и адаптивность.** 420 `sx`-правил — основная трудоёмкость. Переносим их в `Flex`/`Space`/`Row`/`Col` и небольшие CSS-модули, а не в огромные inline-объекты.
4. **Глобальный reset.** `antd/dist/reset.css` может изменить отступы и типографику MUI-страниц. Проверяем визуально уже в Этапе 0.
5. **Контекст уведомлений.** `message`, `notification` и `Modal.confirm` должны вызываться через `App.useApp()`, иначе они не получат тему и локаль.
6. **Многострочные таблицы.** Ant Design `Table` по умолчанию включает пагинацию; для текущих таблиц её нужно явно отключать и проверять прокрутку.
7. **Отсутствие UI-тестов.** Компенсируется ручным чеклистом; при повторных регрессиях возвращаемся к вопросу Playwright.
